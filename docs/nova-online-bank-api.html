Nova Online Bank

Nova Bank Institution Integration API

Version 1.0.0 · OpenAPI 3.0.3 · Nova Sync 101.1

**Nova Online Bank** — REST API for banks, payment institutions, card acquirers, and fintech partners. Protocol version **Nova Sync 101.1** · Visa Card Authorization 101.1 · SWIFT / IBAN rails · Settlement middleware. ## Authentication | Scheme | Header | Use | |--------|--------|-----| | Member JWT | `Authorization: Bearer <token>` | End-user / member operations | | Admin | `X-Admin-Key` | Ledger import, settlement run, funding seed | | Merchant | `X-Merchant-Key` or `X-Nova-Merchant-Key` | Card pre-auth & authorize (merchant API) | | Webhook | `X-Nova-Signature` | Inbound provider webhooks | | Institution | `X-Institution-Api-Key` + `X-Client-Cert-Fingerprint` | mTLS institution API (wires, balances, inbound credit, LP sender) | ## Required headers (member flows) - `X-Nova-Protocol: 101.1` — Nova Sync routing (online m0 / offline m1) - `Idempotency-Key` — required on all `POST` mutations marked idempotent ## Integration entry points 1. **Discovery** — `GET /global/status`, `GET /global/integrations`, `GET /international/integrations` 2. **Popular rail** — `POST /bank/rail/send` (account / IBAN+BIC SEPA or SWIFT / crypto) and `GET /bank/rail/receive`. Dispatches to `POST /fiat/send` and `POST /crypto/withdraw`. Not AI Builder. 3. **Send fiat** — `POST /fiat/send` (Nova Bank API: ledger or SEPA/SWIFT). Canonical member fiat send. `POST /external/transfer` and `POST /transfers/by-party` remain. 4. **Party resolve** — `GET /accounts/resolve` (account # / IBAN) · `GET /external/resolve/{iban}` (thin IBAN wrapper) 5. **Send by party** — `POST /transfers/by-party` (internal account # or external IBAN+BIC — never email) 6. **Inbound credit** — `POST /institutional/inbound/credit` (institution) · `POST /inbound/credit` (admin) · `POST /bank/rail/inbound` · `POST /ledger/import/admin/all-to-account` 7. **International fiat send** — `POST /international/send` (IBAN + BIC → SEPA/SWIFT via `/fiat/send`). Local Ledger auto-promotes to Production. `POST /international/route` remains discovery-only. 8. **Settlement** — `GET /ledger-bridge/status`, `POST /ledger-bridge/settle` 9. **Cards** — merchant pre-auth under `/cards/merchant/*` 10. **Visa JIT** — `POST /visa/marqeta/jit-funding` (network callback) 11. **LP Sender (non-SWIFT API-to-API)** — `GET /lp-sender/framework` · verify / lock / webhooks / LP redemption. Asset value is recognized by the liquidity-providing bank only while the asset-backed ledger is connected to a regulated FI (`GET /lp-sender/ledger/connection`). Live docs: `/api/v1/docs` · Spec: `/api/v1/openapi.json`

Servers

  • https://api.nova-x.io/api/v1 — Public partner API (attach Railway custom domain)
  • https://www.nova-x.io/api/v1 — Public apex (same Nest service)
  • https://api.nova-x.io/api/v1 — Internal Railway origin
  • http://localhost:3000/api/v1 — Local development

Authentication

  • BearerAuth — http bearer. From POST /auth/start
  • AdminKey — apiKey X-Admin-Key.
  • MerchantKey — apiKey X-Merchant-Key. Also accepts X-Nova-Merchant-Key
  • WebhookSignature — apiKey X-Nova-Signature.
  • InstitutionApiKey — apiKey X-Institution-Api-Key. Institution partner API key (hash-stored server-side)
  • MtlsClientCert — apiKey X-Client-Cert-Fingerprint. mTLS client certificate SHA-256 fingerprint (set by API Gateway/ALB)
